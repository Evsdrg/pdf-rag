# 配置说明

本文定义配置的**来源、优先级、密钥边界和生效时机**。安装命令见[部署指南](../DEPLOY.md)，模型迁移和故障处理见[运维手册](OPERATIONS.md)。

## 1. 两类配置与读取优先级

| 类别 | 内容 | 来源与生效 |
|---|---|---|
| 环境/部署常量 | `PDF_ROOT`、`DB_PATH`、密钥、MCP 挂载、监听地址 | 从 `.env` 或进程环境读取，通常需要重启 |
| 可调参数 | 嵌入契约、向量分区、检索、缓存、提取、并发、OCR | 内置默认值 → `.env` 中对应 `env_key` 的初始值 → `data/settings.json` 覆盖值 |

当前注册表有 **56 项可调参数 / 10 个后端分组**。Web 配置中心再按任务组织常用项和高级项，不应把前端任务分类与后端分组数量混为一谈。

`data/settings.json` 是运行时配置，不属于源码。Web 或 `PUT /api/config` 保存覆盖值；单项/全部恢复默认只处理允许调整的参数。密钥 `EMBED_API_KEY`、`OCR_API_KEY`、`ADMIN_TOKEN` **永远只在环境层**，不进入 `config.SPECS`、设置快照、数据包或前端。

测试必须重定向 `SETTINGS_FILE`，不能写穿实际运行配置。

## 2. 常用环境变量

| 变量 | 用途与注意事项 |
|---|---|
| `PDF_ROOT` | 手册根目录；留空使用 `<项目>/pdf`。只接受其下的相对文档路径 |
| `DB_PATH` | LanceDB 目录；留空使用 `<项目>/index.lance` |
| `EMBED_BASE_URL` | OpenAI 兼容的 `/v1` 服务根地址，嵌入与重排共用 |
| `EMBED_API_KEY` | 嵌入/重排服务凭据；不随源码或数据包提供 |
| `EMBED_MODEL` | 新写入向量时使用的当前模型，不是所有旧分区的全局查询契约 |
| `EMBED_DIMENSIONS` | 新分区的向量维度；查询时仍以各分区元数据为准 |
| `EMBED_INPUT_TYPE_DOC` / `EMBED_INPUT_TYPE_QUERY` | 建库/查询输入类型，Cohere 等模型需要成对配置 |
| `RERANKER_MODEL` | 重排模型，不改变向量空间 |
| `OCR_API_KEY` | 远程 OCR 凭据，只在环境层 |
| `ADMIN_TOKEN` | 管理接口令牌；留空时 `/api/admin/*` 返回 403 |
| `MCP_INPROC` | 默认 1，MCP 与后端同进程挂载 `/mcp`；设 0 时独立运行 `server.py` |
| `BACKEND_HOST` / `BACKEND_PORT` | 监听地址和端口，默认 `127.0.0.1:8100` |

`.env.example` 是示例，不是所有部署都应照抄的服务契约。完整可调项及范围以 Web 配置中心和 `backend/config.py` 注册表为准。

## 3. 向量模型与分区选择

每个向量分区由 `model + dim + input_type_doc` 标识，元数据还记录查询所需的 `input_type_query`。查询向量必须按**被选中分区的契约**生成，不能仅按当前 `.env` 猜测。

- `vector_models_priority`：逗号分隔的分区 slug 或模型名，决定检索顺序；留空时只使用当前配置对应的分区。
- `vector_models_exclude`：排除指定分区或模型，与优先级冲突时以排除为准。
- 同一查询可使用多个分区，但同一个块只采用第一个命中的向量；不同模型的距离不混算。
- `vector_coverage_min` 默认 1.0。分区没有覆盖全部主表块时会标记降级；FTS/子串仍可召回。
- 分区选择或覆盖不足不等于文档不存在。用 `/api/stats` 看分区覆盖，用 `/api/v2/status` 看源文件与索引覆盖。

详细设计见[向量分区](VECTOR-PARTITION.md)。

### 更换或新增模型

1. 将 `embed_model`、维度、输入类型和服务地址设为新契约。
2. 普通增量索引只给**本轮变化文件**写新分区，不代表完整迁移。
3. 需要让新模型覆盖全部块时，先把它设为当前模型，再运行：

   ```bash
   uv run python -m backend.ingest --rebuild-vectors <同名模型>
   ```

4. 配置 `vector_models_priority` 选择目标分区，并检查覆盖率。
5. 旧分区默认保留，便于回退；`--drop-old-vectors` 只清理目标模型自己的分区，默认关闭，不能当作通用清理命令。

`--rebuild` 是**重建主表文本**的操作，向量分区不动；文件内容、提取配置与分块结果不变时 uid 保持稳定。它不是换模型的专用命令，也不应被描述成所有模型变化的唯一选择。

## 4. 检索与缓存

- `snippet_width` 控制返回片段目标宽度；`window_stride_div` 控制窗口定位精细度。
- 候选池和重排池分别由 `cand_*`、`rerank_pool_*` 控制。修改它们会改变检索质量与上游载荷，应按[评测方法](BENCHMARKS.md#6-测试方法学)验证。
- `max_per_doc` 限制同一文件结果数，跨型号比较时可避免单文档占满结果。
- 查询缓存键包含影响结果的参数、表版本和分区选择。配置改变后不能继续返回旧参数的结果。
- **降级结果不缓存**，避免临时故障被固化到 TTL 内。
- `page_max_chars` 是单页/多页/章节的默认文本预算，单次实际预算最高 12000；超出部分通过游标继续，不再静默截断。

`rerank_score` 是相关性信号，不是答案正确率概率。型号身份提示也不能替代原文核对。

## 5. 本地解析与嵌入并发

| 参数 | 作用 | 生效时机 |
|---|---|---|
| `extract_workers` | 同时解析多少份本地文档，包含文本、表格和渲染 | 下一轮索引 |
| `ocr_workers` | 整轮索引共享的 OCR 请求通路数，同一 PDF 也可多页并行 | 下一轮索引 |
| `embed_batch` | 每次嵌入请求携带的块数 | 后续嵌入请求 |
| `embed_workers` | 嵌入请求并发数 | 后续索引任务 |

`extract_workers × ocr_workers` **不是**总 OCR 并发；实际请求上限由共享的 `ocr_workers` 决定。读页接口不属于索引 OCR 池。增加并发前应同时考虑 CPU、内存、服务商限流和本地 OCR 算力，不能只根据逻辑核数放大。

## 6. OCR 与文本提取

- `ocr_backend=local` 使用本机 Paddle 服务；`remote` 使用 OpenAI 兼容视觉接口。地址、模型和提示词属于可调参数，密钥仍只在环境层。
- `ocr_min_chars` 是低文本候选线，不是“低于此值就一定 OCR”的硬规则。
- `ocr_smart_filter` 结合整份文档的低文本分布、连续段、图片、矢量和页面文字位置，证据不足时保留 OCR；关闭后恢复仅按字数触发。
- `min_chars_per_page` 是文档提取质量告警线，不是 OCR 触发线。
- 改变策略不会自动重提取旧文件；需要由用户显式重跑指定文件或索引任务。
- OCR 失败时读页保留可用原生文本并返回 `warnings`，错误提示不会冒充手册正文。

策略与并发边界见[架构设计](ARCHITECTURE.md#5-索引构建流水线)。

## 7. 运行与排障约束

- 系统不主动、定时探测嵌入、重排或 OCR 服务。状态只反映本地配置、索引和最近一次真实调用。
- 要验证上游能力，应执行一次真实业务查询，并同时检查响应中的 `degraded/notice/warnings`。
- 环境常量改变通常需要重启；检索参数即时生效；索引并发在下一轮任务生效；运行中的池不动态扩缩容。
- 保存配置不等于重建索引。模型、提取策略或语料变化后，按[运维手册](OPERATIONS.md)选择最小必要操作。

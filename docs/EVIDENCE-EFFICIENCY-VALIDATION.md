# 证据效率逐项验证（2026-11-01）

## 方法与冻结边界

起点 `c640ece`，实验仍在 `feat/sag-entity-bridge-20261031`。本轮验证来源约束、
参数/条件/数值角色绑定、缺失证据补查和紧凑分层输出，不引入完整 SAG 引擎。
所有实验只读同一现有索引，禁止 socket 网络，不请求 embedding/rerank/OCR，不 ingest。
原型不接入生产 API，不改变现有搜索默认行为。

`eval_evidence_efficiency.json` 固定20道新参数/来源/负例/多参数题，17个页证据目标。
SHA256：`a4fa67c3cb778242ee5f61f8017e86a0b6c7322cd59eb1c9bf3f19ad95628adb`。
题目在修改原型前冻结，没有按检索预测筛题；仍是同库且由本会话审校的新意图集，
不是独立人员编写的无偏留出集。块锚点校验仅证明文字存在，不自动证明参数行列正确。
后续若改冻结题，必须另立数据版本并重新声明比较范围。

输入 `model/source_terms/revision/needs` 是显式任务约束，不从评测真值注入来源文件、
页、uid或答案数值。基线问题文字也包含这些条件；原型使用结构化输入，不能混称
纯自然语言自动解析效果，解析器成本和错误本轮未覆盖。

## 计量

- 页和片段覆盖：必须指定文件和物理页，且含审校所需字面值，非最终回答准确率。
- 来源负例：不存在的来源/版本及未指定而歧义的来源不得默默回退。
- 表行绑定：参数、显式条件和数值角色必须由同一完整行提供；全局条件/脚注另保留，
  只返回“行证据”，不声称条件完整适用。
- 上下文：同时记录响应UTF-8字节、字符、确定性词法单元代理；**不等于模型token**。
  任务链代理为每次决策重新携带此前工具响应的前缀累计字节，固定策略模拟，不是真实Agent。
- 不安装/联网下载分词器；本地没有目标模型tokenizer，实际token与账单结论留空。

## 修原型前基线

`tools/eval_evidence_efficiency.py` 默认走现有 structured FTS/无重排，两轮独立进程：

| 指标 | 结果 |
|---|---:|
| 证据页覆盖 | 15/17（88.2%） |
| 参数/条件字面片段覆盖 | 12/17（70.6%） |
| 正例全页齐全 | 12题 |
| 工具调用 | 20 |
| 响应总字节 | 227703 |
| 降级 | 0 |

此基线不会自动拒绝负例或绑定表格角色，不能把“有返回结果”计作成功。
它也尚未补读整页，后续紧凑输出须与同等证据完整度的流程比较，而不能只比较短响应。

## 1. 显式来源约束

`backend/evidence_probe.py` 为隔离原型，只接收任务明确给出的型号、来源词、版本；
在既有model_no及文件/标题/首页中核对字面来源，未知或多个不同内容来源返回拒绝/歧义，
不猜厂商、不自动升版。同字节别名只保一个引用，不确认订购身份。

两轮 source 变体均将S03不存在版本、S06未知厂商和S07未指定厂商歧义正确拦下，
S01/S02/S04/S05均选择其指定来源。全题页覆盖13/17、片段10/17，低于无约束基线15/17、12/17；
响应总字节186874，下降部分来自拒绝和召回减少，不可据此声称等效证据的压缩收益。
**结论：来源约束有防止串用的价值，但不能单独保证参数召回；不建议仅加硬过滤就上线。**
型号前缀与字面来源是保守原型，不是自然语言来源解析或可靠厂商元数据替代。

## 2. 参数/条件/角色同行绑定

原型仅对完整Markdown表中参数（或符号）精确匹配、指定角色存在、整段字面条件一致的行
返回绑定。多个不同值/条件候选不择优猜测；缺失最大值、错误条件、空白参数需继承均留missing。
微符号/空白宽容，mA与MA仍不同。`context_status=requires_page_context` 强制说明表外共同条件
及脚注尚待回读，尤其HE9073的Dropout(1)不能仅凭行值宣布完整适用。

两轮绑定相同：17条行绑定，独立评分重新按引用表头/列与数据行回查，无错误列绑定；
N01/N02/N03均无绑定。P01和M02的频率需求因页未召回仍missing，不放宽条件来凑数。
页/片段覆盖不变（13/17、10/17），响应增至196143字节。
**结论：严格绑定提高可检查性并能拒绝明显错配，但覆盖有限，增加字段会增大上下文；
这不是最终答案正确率，也未证明表外条件已经完整。**

## 3. 缺失证据驱动的补查

每题最多3次，仅对仍missing的显式参数在已确认来源内本地字面补查；每次最多2页，
来源扫描最多512块/200万字符，超限不以半库结果冒充完整。已满足需求不再重复查询。
新页仍需经过同一保守行绑定，拒绝条件不符或缺失角色；整个流程不接收gold页或答案值。

两轮refill结果一致：页/片段覆盖回到15/17、12/17，绑定17→19条，独立表列回查均有效，
负例仍0绑定；P01与M02缺页被补回。调用20→25次，响应208383字节，固定累计历史代理
264475字节，高于单轮绑定196143字节。
**结论：补查能补召回缺口，但增加轮次会增加累计上下文；不等于自动省token。**
三次无安全答案的负例也产生空补查，这正是需要成本与拒绝策略一起衡量的代价。

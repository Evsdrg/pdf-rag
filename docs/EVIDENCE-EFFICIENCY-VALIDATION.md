# 证据效率逐项验证（2026-11-01）

## 方法与冻结边界

起点 `c640ece`，实验仍在 `feat/sag-entity-bridge-20261031`。本轮验证来源约束、
参数/条件/数值角色绑定、缺失证据补查和紧凑分层输出，不引入完整 SAG 引擎。
所有实验只读同一现有索引，禁止 socket 网络，不请求 embedding/rerank/OCR，不 ingest。
原型不接入生产 API，不改变现有搜索默认行为。

`eval_evidence_efficiency.json` 固定20道新参数/来源/负例/多参数题，17个页证据目标。
SHA256：`a4fa67c3cb778242ee5f61f8017e86a0b6c7322cd59eb1c9bf3f19ad95628adb`。
题目在修改原型前冻结，没有按检索预测筛题；正例按可提取/可审校表行选取，对现有解析器
有选择偏差。仍是同库且由本会话审校的新意图集，不是独立人员编写的无偏留出集。
块锚点校验仅证明文字存在，不自动证明参数行列正确。
后续若改冻结题，必须另立数据版本并重新声明比较范围。

输入 `model/source_terms/revision/needs` 是显式任务约束，不从评测真值注入来源文件、
页、uid或答案数值。基线问题文字也包含这些条件；原型使用结构化输入，不能混称
纯自然语言自动解析效果，解析器成本和错误本轮未覆盖。

## 计量

- 页和片段覆盖分别报告指定文件和同MD5内容别名两种口径，都约束物理页及所需字面值，
  不把内容等同解释成订购身份已确认，也不是最终回答准确率。
- 来源负例：不存在的来源/版本及未指定而歧义的来源不得默默回退。
- 表行绑定：参数、显式条件和数值角色必须由同一完整行提供；全局条件/脚注另保留，
  只返回“行证据”，不声称条件完整适用。
- 上下文：同时记录响应UTF-8字节、字符、确定性词法单元代理；**不等于模型token**。
  任务链代理为每次决策重新携带此前工具响应的前缀累计字节，固定策略模拟，不是真实Agent。
- 不安装/联网下载分词器；本地没有目标模型tokenizer，实际token与账单结论留空。

## 修原型前基线

`tools/eval_evidence_efficiency.py` 默认走现有 structured FTS/无重排，两轮独立进程：

| 指标 | 结果 |
|---|---:|
| 证据页覆盖 | 15/17（88.2%） |
| 参数/条件字面片段覆盖 | 12/17（70.6%） |
| 正例全页齐全 | 12题 |
| 工具调用 | 20 |
| 响应总字节 | 227703 |
| 降级 | 0 |

此基线不会自动拒绝负例或绑定表格角色，不能把“有返回结果”计作成功。
它也尚未补读整页，后续紧凑输出须与同等证据完整度的流程比较，而不能只比较短响应。

## 1. 显式来源约束

`backend/evidence_probe.py` 为隔离原型，只接收任务明确给出的型号、来源词、版本；
在既有model_no及文件/标题/首页中核对字面来源，未知或多个不同内容来源返回拒绝/歧义，
不猜厂商、不自动升版。同字节别名只保一个引用，不确认订购身份。

两轮 source 变体均将S03不存在版本、S06未知厂商和S07未指定厂商歧义正确拦下，
S01/S02/S04/S05均选择其指定来源。同MD5别名允许时页/片段覆盖14/17、11/17；
严格指定文件口径13/17、10/17，低于无约束基线15/17、12/17。S04选了同字节A2文件而非
标注A1文件，计内容覆盖但不能确认A1料号；来源正例的不同内容命中从基线9条降为0。
正式协议口径响应186823字节，下降部分来自拒绝和召回减少，不可称等效证据的压缩收益。
**结论：来源约束有防止串用的价值，但不能单独保证参数召回；不建议仅加硬过滤就上线。**
型号前缀与字面来源是保守原型，不是自然语言来源解析或可靠厂商元数据替代。

## 2. 参数/条件/角色同行绑定

原型仅对完整Markdown表中参数（或符号）精确匹配、指定角色存在、整段字面条件一致的行
返回绑定。多个不同值/条件候选不择优猜测；缺失最大值、错误条件、空白参数需继承均留missing。
微符号/空白宽容，mA与MA仍不同。`context_status=requires_page_context` 强制说明表外共同条件
及脚注尚待回读，尤其HE9073的Dropout(1)不能仅凭行值宣布完整适用。

两轮绑定相同：17条行绑定，独立评分重新按引用表头/列与数据行回查，无错误列绑定；
N01/N02/N03均无绑定。P01和M02的频率需求因页未召回仍missing，不放宽条件来凑数。
页/片段覆盖不变（指定文件13/17、10/17；同字节14/17、11/17），正式协议响应增至196059字节。
**结论：严格绑定提高可检查性并能拒绝明显错配，但覆盖有限，增加字段会增大上下文；
这不是最终答案正确率，也未证明表外条件已经完整。**

## 3. 缺失证据驱动的补查

每题最多3次，仅对仍missing的显式参数在已确认来源内本地字面补查；每次最多2页，
来源扫描最多512块/200万字符，超限不以半库结果冒充完整。已满足需求不再重复查询。
新页仍需经过同一保守行绑定，拒绝条件不符或缺失角色；整个流程不接收gold页或答案值。

两轮refill结果一致：指定文件页/片段覆盖回到15/17、12/17，同字节内容为16/17、13/17，
绑定17→19条，独立表列回查均有效，负例仍0绑定；P01与M02缺页被补回。
调用20→25次，正式协议响应204516字节，固定累计历史代理260608字节，高于单轮绑定196059字节。
**结论：补查能补召回缺口，但增加轮次会增加累计上下文；不等于自动省token。**
三次无安全答案的负例也产生空补查，这正是需要成本与拒绝策略一起衡量的代价。

## 4. 紧凑分层输出与累计上下文

紧凑层不缩短snippet，不删绑定的参数/条件/单位/数值角色或引用，不隐藏missing/degraded。
仅省去检索轨迹、非请求参数的重复表格投影及常规冗余字段，保留可再次取得详情的提示。
先应用正式Agent API已有的snippet_ref.text去重，再比较，避免把既有优化算成新收益。
逐题逐字核验20题共89个命中，full/compact的file/page/snippet、bindings/missing完全相同。

公平比较是refill与compact：同25次初查/补查、同19条行绑定；双方再按绑定引用回读相同的
15份索引页上下文（每8000字符续读，不静默截断），包含共同条件与脚注可见文本。
这仍是固定本地策略模拟，不是模型回答或实时PDF提取，未证明读到上下文就理解了条件。

| 同等证据范围的成本 | 全字段refill | compact | 变化 |
|---|---:|---:|---:|
| 初查/补查响应字节 | 204516 | 158778 | -22.4% |
| 加相同上下文后的调用 | 40 | 40 | 不变 |
| 加相同上下文后的响应字节 | 267695 | 221957 | -17.1% |
| 固定累计输入历史字节代理 | 533024 | 426519 | -20.0% |

页/片段覆盖均15/17、12/17，绑定19条，独立表列/单位回查0错误，负例0绑定。
早期未套正式协议时的字节数是阶段记录；此表为最终公平口径。
**结论：按需诊断、去重复元数据值得投入，确能减少相同正文证据的载荷；
没有目标模型tokenizer与真实Agent实验，不能宣称实际token/账单同比例下降或答案准确率不变。**

## 5. 结论、成本及未验证门槛

| 方向 | 直接观察 | 投入建议 |
|---|---|---|
| 显式来源约束 | 来源正例不同内容命中9→0，三类来源歧义/不存在被拦下，但单独过滤丢参数页 | 值得优先，但要与补查一起做；不能把前缀或同字节当料号确认 |
| 同行条件与角色绑定 | 17→19条可回溯绑定，三类错条件/缺角色/空格继承负例0绑定 | 值得保守投入；不做单位猜修、条件推理或跨表继承 |
| 缺失证据补查 | 补回2需求，25次初查/补查而非20次，未解决负例也有空查询成本 | 按需、有界；不建议无条件多跳扩展 |
| 紧凑输出 | 同snippet/绑定/上下文的响应-17.1%、累计历史代理-20.0% | 优先级高；先分离诊断/非请求事实，不裁正文条件 |
| 完整SAG建图/更深多跳 | 本轮未引入，没有支持其成本收益的新证据 | 暂不投入 |

最终两轮冻结指纹与代码/索引指纹一致，全部变体无降级；293项后端测试通过，文档与diff检查通过。
此轮未动前端、pi或协议入口，所以未重跑前端浏览器/构建或pi测试，不沿用此前通过状态冒充本轮验证。
生产检索核心、实体、词法、表格提取、Agent入口相对`c640ece`无改动；原型仅由离线工具/测试引用。
没有新模型请求、可用性探测、OCR、ingest、生产索引/设置修改、部署、推送或安装依赖，未启动子代理。

不可用平均数掩盖的限制：

- 同字节内容仅16/17页、13/17片段（严格指定文件15/17、12/17），不是全题正确。
- 来源别名、正文省略后缀及结构化显式输入均可能影响实际Agent行为；本轮没有验证自然语言解析器。
- 表格切块、空白合并格、单位损坏、全局共同条件与脚注仍须回读；原型每条绑定都标requires_page_context。
- 紧凑层明确不发送非请求表格投影/轨迹，不是完整原响应无损压缩；只验证保留的正文/绑定/上下文等价。
- 固定成本模型只计工具响应及重复携带历史，未计提示词、请求参数、推理、最终答案或详情按需重取；
  不能与单轮无绑定基线直接宣称同质量降耗，新增详情请求可能抵消节省。
- 本地无目标模型tokenizer，实际token/账单和真实Agent最终答案未验证；应在另获模型请求授权后单独测试。
- 所有方向仍是离线原型，不构成生产API/schema或默认开启授权。

## 复现

```bash
# 每个variant独立进程，两轮；工具内部封锁socket且关闭结果缓存（不持久化）
for repeat in 1 2; do
  for variant in baseline source binding refill compact; do
    .venv/bin/python tools/eval_evidence_efficiency.py --variant "$variant" --json "/tmp/evidence-${variant}-${repeat}.json"
  done
done
.venv/bin/python -m unittest discover -s tests
.venv/bin/python tools/check_docs.py
git diff --check
```

JSON输出只保存必要指标/命中引用/短表行投影，不包含凭据；仍含手册信息，应仅留本地。
完整手册窗口、采样上下文、重复响应与逐字比较产物留在独立本地实验目录，不提交到仓库。

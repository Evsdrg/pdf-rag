## 内容分层约定

1. **当前契约**：接口字段、配置优先级、命令行为，以当前代码和实测为准。
2. **历史实验**：必须带环境、样本范围和日期；不能写成当前生产指标或对所有数据的保证。
3. **内部状态**：某台机器的地址、账号、文档数量和运行路径只留在内部记录，不混入公开文档。
4. **设计理由与操作步骤分开**：为什么这样做放架构/向量分区，怎样执行放部署/运维。
5. **字段语义与端点清单分开**：协议文档解释数据含义，HTTP 参考列出路径；避免两份完整表格各自漂移。
6. **可变数字谨慎引用**：文档数、块数、包数量、性能数据不写成永久事实；确需保留时标明测量环境。
7. **保留否定性结果**：已被实验否决的方案不能因文档精简又变成推荐做法。
8. **不隐藏不确定性**：离线测试、真实业务抽查和完整评测必须区分，不把协议通过写成检索准确率提升。

## 修改后的检查

- 改接口时同步协议、HTTP 参考、客户端说明和必要的契约测试。
- 改配置或命令时同步配置说明、运维手册、`.env.example` 和交付包文本。
- 改架构时检查相关不变量，避免把历史实现步骤写成当前约束。
- 链接使用相对当前文件的路径；移动文件后先查引用。
- 运行 `python tools/check_docs.py` 检查被跟踪文档的链接和敏感信息。
- `.env` 只保存本机配置与密钥；`.env.example` 只保留示例。手册、索引、运行数据和内部运维记录不提交。发布源码以 `git archive HEAD` 为准。
